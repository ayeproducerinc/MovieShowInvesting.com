---
name: Account-switch visitor handoff
description: Authentication switches that preserve private ownership and browser popup activation.
---

When a browser switches authenticated accounts or identity providers, rotate an account-owned visitor cookie **while the old verified identity is still available**. Do not rotate an unclaimed guest cookie merely because a user is signing in. For Google popup account selection, any network-based visitor-cookie rotation must finish on a first explicit click; open the popup on a second click so it still has direct user activation. This is different from preserving an unclaimed filmmaker worksheet: its prepared, exact-draft save may finish alongside a synchronously opened popup, but claiming must wait for successful preservation. Investor worksheet progress needs account ownership even before the first interest is submitted; a guest cookie must not be the fallback for a signed-in draft. Bind queued investor saves to the identity captured when the worksheet opened and reject mismatches on the server; cancelling queued work cannot stop an already-sent request. If an unfinished guest worksheet and an account worksheet coexist, preserve both separately rather than replacing either set of answers.

New filmmaker submission requires a draft that was already linked to the exact verified provider and UID. Do not simplify final submission into an implicit guest claim. An unfinished-draft claim must include its expected draft ID and validate that ID under the same transaction as the browser proof and account-conflict checks; legacy completed-submission claims remain a separate path.

Account-project start, resume, and selection must also retain the cookie for an unfinished, meaningful, unlinked guest pitch, including material-only drafts. Until it is linked, refuse a cookie-changing account action with an actionable conflict rather than stranding it. If another active account draft prevents linking, finish that account draft in another browser/device and then return to the original browser. Account-linked drafts may switch normally.

**Why:** An old account's visitor cookie can make a new account's project or investor operations fail closed, even after query caches are cleared. A cookie-only investor progress read could expose private answers to a later user of that browser, while an autosave queued before an account switch can run with the next account's current token. Awaiting a server call before opening an OAuth popup may cause browsers to block it. An implicit claim during final submission can bypass the conflicting-account-draft check, and checking a draft only before an HTTP request does not prevent another tab from changing the shared visitor cookie before that request arrives. The guest cookie is the only recoverable proof for an unlinked draft: retaining its database row or a session-stored draft ID is not enough. A rotation guard is the smallest safe MVP solution without adding a separate proof-backup/recovery system.

**How to apply:** Check both filmmaker and investor ownership when leaving an account and before reading or saving progress; fail closed if safe preparation fails. Keep account drafts independent of browser-guest drafts and assert the draft's captured identity at every delayed write. When changing to a popup-based identity, separate cookie preparation and popup opening into distinct user actions, then revalidate the current identity before using prepared state.
